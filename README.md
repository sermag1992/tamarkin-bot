# Бот автопостинга для Telegram-канала «Тамаркин.Маркетинг»

Работает в режиме личного одобрения: бот не публикует ничего сам.
Каждую свежую новость он присылает владельцу в личку с кнопками
«✅ Опубликовать» / «⏭ Пропустить» — в канал уходит только одобренное.

Пайплайн кандидата: RSS-ленты → фильтр по ключевым словам → дедупликация →
карточка в личку владельцу (обложка статьи + заголовок + суть + ссылка).
Публикация одобренного: хук-строка и переписанная суть (Pollinations text API) →
картинка из RSS (fallback: генерация) → пост в канал (aiogram, HTML, ссылка на источник).

## Файлы

| Файл | Назначение |
|---|---|
| `config.py` | чтение настроек из переменных окружения / `.env` |
| `news_parser.py` | RSS, фильтры, дедупликация, обложки |
| `approvals.py` | карточки кандидатов в личку, кнопки, команды «публикуй»/«пропустить» |
| `text_hook.py` | цепляющая строка-хук и переписанная суть поста |
| `image_generator.py` | картинка: обложка RSS / Pollinations / OpenAI, retry-логика |
| `telegram_poster.py` | форматирование и отправка поста в канал |
| `main.py` | цикл: решения владельца → новые кандидаты |
| `diagnostics.py` | проверка токена и канала (воркфлоу diagnostics) |

Состояние между прогонами хранится в репозитории:
`posted.json` (опубликованные хэши), `pending.json` (очередь кандидатов),
`owner.json` (владелец, привязывается по /start), `updates_offset.json` (сдвиг Telegram-обновлений).

## Как работает владелец

1. Написать боту `/start` в Telegram (один раз).
2. Бот присылает карточки новостей с кнопками: ✅ Опубликовать / ⏭ Пропустить.
3. В канал уходит только одобренное. Можно управлять словами:
   «публикуй» (вся очередь), «публикуй 2» (конкретная), «пропустить 1».
4. Реакция применяется в течение ~30 минут (расписание воркфлоу) или сразу
   после ручного запуска (Actions → Run workflow).

## Запуск в GitHub Actions

1. Репозиторий залит на GitHub (ветка `master`).
2. Секреты (Settings → Secrets and variables → Actions):
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`.
3. Воркфлоу `bot.yml` срабатывает по расписанию и вручную;
   `diagnostics.yml` — только вручную (проверка токена/канала).
4. Бот должен быть администратором канала.

## Запуск локально (на ПК)

```powershell
pip install -r requirements.txt
copy .env.example .env   # заполнить TELEGRAM_BOT_TOKEN и TELEGRAM_CHANNEL_ID
python main.py
```

## Настройки (переменные окружения / .env)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | обязательно |
| `TELEGRAM_CHANNEL_ID` | — | обязательно |
| `RSS_URLS` | — | обязательно, ленты через запятую |
| `CANDIDATES_PER_RUN` | `3` | кандидатов в личку за один прогон |
| `MAX_PENDING` | `5` | максимум в очереди одобрения |
| `PENDING_TTL_HOURS` | `24` | сколько ждать решения по кандидату |
| `IMAGE_MODE` | `rss` | `rss` (обложка) / `pollinations` / `openai` |
| `TEXT_HOOK_ENABLED` | `1` | хук-строка и переписанная суть |
| `LLM_FILTER_ENABLED` | `1` | LLM отсекает новости не по теме канала до отправки владельцу |
| `CHECK_INTERVAL_MINUTES` | `60` | период цикла; `0` — одиночный прогон (CI) |
| `MAX_NEWS_AGE_HOURS` | `24` | свежесть новостей |
| `KEYWORDS` | см. config.py | тематический фильтр |
| `STOPWORDS` | см. config.py | отбраковка |
| `OPENAI_API_KEY` | — | только для `IMAGE_MODE=openai` |
| `TELEGRAM_API_BASE` | `https://api.telegram.org` | сменный API-адрес |
| `POSTED_JSON_PATH` / `PENDING_JSON_PATH` | файлы состояния | хранилища хэшей и очереди |

## Если что-то не выходит

- Кандидаты не приходят: убедись, что написал боту `/start`.
- Пост не выходит после «публикуй»: бот должен быть админом канала.
- Смотреть лог: Actions → прогон → шаг «Обработать решения владельца…»;
  локально — консоль и `bot.log`.
